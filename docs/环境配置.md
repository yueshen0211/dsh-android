## 1. 一句话总结

**只需 Windows + PowerShell + `PATH` 上的 `node`/`npm`，其余全部自动下载进工作区 `.toolchain\`。**

工具链**不装到系统**、**不需要管理员权限**、**不修改系统环境变量**——所有 `JAVA_HOME` / `ANDROID_HOME` /
`GRADLE_USER_HOME` / `npm_config_cache` 都在**当前 shell 内**指向工作区。新开一个 shell 就重新
`. tools\android-env.ps1` 一次。

```powershell
. D:\Work\DSHapk\tools\android-env.ps1      # 每个新 shell 的第一条命令
```

三条设计取舍，理解了就不会走弯路：

| 取舍 | 原因 |
|---|---|
| **不用 Gradle**，直驱 `aapt2 → javac → d8 → zipalign → apksigner` | Gradle 守护进程在本沙箱内无法启动（见 [§7.1](#71-gradle-守护进程无法启动)） |
| **不用系统 SDK**，全落在 `.toolchain\sdk` | 沙箱只允许写 `D:\Work\DSHapk`，系统路径写不了 |
| **`python` / `node` 是仅有的两个外部依赖** | `python` 用于解 `.deb`，`node` 用于下载与 ELF 改写；`tar` / `robocopy` 由 Windows 自带 |

## 4. 从零复现：完整步骤

> 每一步都可以单独重跑；脚本对已存在的产物**跳过而非重做**（下载带缓存，见 `Get-FileOnce`）。

### 4.1 装工具链

**① JDK 21（Temurin）**

```
https://api.adoptium.net/v3/binary/latest/21/ga/windows/x64/jdk/hotspot/normal/eclipse
```

解压到 `.toolchain\jdk-21\`。⚠️ zip 内**多套一层版本目录**（`jdk-21\jdk-21.0.12.1+1\bin\javac.exe`），
`android-env.ps1` 靠**搜 `bin\javac.exe`** 定位，所以不要假设 JDK home 就是顶层那个目录。

**② Android commandline-tools 22.0**

```
https://dl.google.com/android/repository/commandlinetools-win-13114758_latest.zip
```

解压到 `.toolchain\sdk\cmdline-tools\latest\`（路径必须是 `latest`，脚本按此硬编码）。

**③ SDK 组件**

**④ 可选：Gradle 8.9**（当前构建链不用，仅备用）

```powershell

# 每个想支持的 ABI 各跑两遍：arm64-v8a（真机）、x86_64（模拟器）
```

> 而 nodejs-mobile 停在 18.20.4、puerts 停在 16.16。

## 5. 环境变量与目录重定向

全部逻辑集中在 **`tools\android-env.ps1`**（74 行，ASCII-only，dot-source 使用）。
它**只影响当前 shell**，退出即失效，不碰系统环境变量。

### 5.1 为什么必须重定向

本沙箱的写权限只覆盖 `D:\Work\DSHapk`，而这些工具默认都往用户目录写：

| 变量 | 默认值 | 重定向到 | 不重定向的症状 |
|---|---|---|---|
| `ANDROID_USER_HOME` | `%USERPROFILE%\.android` | `.toolchain\android-user-home` | `sdkmanager`：`Failed to download any source lists!`（**伪装成网络故障**） |
| `ANDROID_PREFS_ROOT` | 同上 | 同上 | `adb`（platform-tools 35+）读的是这个而不是 `ANDROID_USER_HOME`，两个都要设 |
| `ANDROID_SDK_HOME` | 同上 | 同上 | 旧工具链使用 |
| `ANDROID_AVD_HOME` | `<user-home>\avd` | `.toolchain\android-user-home\avd` | `emulator` 找不到 AVD |
| `GRADLE_USER_HOME` | `%USERPROFILE%\.gradle` | `.toolchain\gradle-home` | Gradle 写不出去（虽然本环境不用 Gradle） |
| `npm_config_cache` | `%LOCALAPPDATA%\npm-cache` | `.toolchain\npm-cache` | `npm` 写不出去 |

### 5.2 同时设置（不重定向）

| 变量 | 值 | 说明 |
|---|---|---|
| `JAVA_HOME` | `.toolchain\jdk-21\jdk-21.0.12.1+1` | 靠搜 `bin\javac.exe` 定位，不猜目录层级 |
| `ANDROID_HOME` / `ANDROID_SDK_ROOT` | `.toolchain\sdk` | 两个都设，工具各认一个 |
| `ANDROID_NDK_HOME` | `.toolchain\sdk\ndk\27.0.12077973` | |
| `PATH` | `JDK\bin` + `cmdline-tools\latest\bin` + `platform-tools` + 原 `PATH` | 前置，保证优先用工作区版本 |

### 5.3 `~/.android` 必须存在

`adb.exe`（platform-tools 37）**硬编码** `~/.android`，且**不认上述任何环境变量**。
该目录缺失时任何 adb 调用都直接崩溃。所以：

```powershell
New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\.android" | Out-Null
```

> 注意这与重定向并不矛盾：`adb` 仍会去碰 `~/.android`，只是它需要**存在**即可，写不写得到无所谓。

### 5.4 脚本如何定位工具链（两个易踩的坑）

`android-env.ps1` 与 `build-apk-cli.ps1` 都是**运行时搜索**而非硬编码路径：

1. **JDK 靠搜 `bin\javac.exe`**（`-Depth 3`），因为 zip 内多一层 `jdk-21.0.12.1+1\`。
2. **不要用通配符穿过 `.toolchain` 段**：路径里的 `.` 是通配符字符，`Get-ChildItem .toolchain\*` 这类写法会静默匹配不到东西。
   脚本一律用 `-LiteralPath`。

### 5.5 脚本必须 ASCII-only

本机 shell 是 **Windows PowerShell 5.1**，它**在没有 BOM 时按 ANSI 解码 `.ps1`**——
非 ASCII 字符可能破坏字符串终止符。所以 `tools\*.ps1`、`tools\m1\*.ps1` 全部刻意保持 ASCII-only
（生成 `package.json` 时也用 `UTF8Encoding($false)` 写无 BOM UTF-8）。
新增脚本请沿用这个约定。

实测：`tools\` 下 **10 个 `.ps1` 文件非 ASCII 字节数均为 0**。

**同一个 5.1 约束还影响语法**：`??`（空合并运算符）等 PS 7 语法**不可用**，会直接解析失败。
写判断请用 `if (-not $x) { … }`：

```powershell
# ✗ PowerShell 5.1 不支持，解析即失败
$src = (Get-Command $t -ErrorAction SilentlyContinue).Source ?? '(not on PATH)'

# ✓
$src = (Get-Command $t -ErrorAction SilentlyContinue).Source
if (-not $src) { $src = '(not on PATH)' }
```

### 5.6 GitHub 发布凭据

发布用 `gh` CLI，**必须**用它而不是 REST API：GitHub REST 上传资产上限 **100 MB**，
而 APK 有 140 MB，`gh` 会分块上传。

```powershell
.\tools\install-gh.ps1      # 一次性下载安装到 .toolchain\gh\
. .\tools\gh-env.ps1        # 从 Windows 凭据管理器取 token 注入 GH_TOKEN（仅当前 shell）
```

凭据现状：

- **SSH 不可用**：`~/.ssh/id_ed25519` 未在 GitHub 授权（`Permission denied (publickey)`）。
- **HTTPS 可用**：凭据管理器存有 GitHub OAuth token（`gho_`，scopes: `gist, repo, workflow`）。
- **`gh auth login` 用不了**：它要求 `read:org`，该 token 没有；但通过 `GH_TOKEN` 注入可绕过该校验。

`gh-env.ps1` **不落盘、不打印、不进命令行**，token 只存在于当前进程环境，shell 退出即消失。

## 7. 已知环境限制

### 7.1 Gradle 守护进程无法启动

**结论：Gradle 在本沙箱内不可用。** 任何需要守护进程的任务都死在：

```
Caught exception: Couldn't open current thread, error = 5
```

| 验证 | 结果 |
|---|---|
| `gradle --version`（不起守护进程） | ✅ 通过 |
| `gradle help` / `tasks` / `assembleDebug` | ❌ 全部失败 |
| Java 新建线程、线程池 | ✅ 正常 |
| Java 启动子进程（`ProcessBuilder`） | ✅ 正常 |

即 **JVM 没问题，是守护进程启动被拦**：守护进程通过 `native-platform.dll` 调 `OpenThread`
并请求 `THREAD_SET_INFORMATION`，本沙箱的进程令牌不允许。

**应对（已落地）**：`tools\build-apk-cli.ps1` 绕开 Gradle，直驱
`aapt2 link → javac → d8 → jar uf → zipalign → apksigner`。对当前的纯 Java 壳足够。
**何时必须回到 Gradle**：引入 Kotlin、AndroidX、复杂资源合并或多模块构建时——
届时选择：① 在沙箱外的普通终端跑；② 放开沙箱权限；③ 走 CI。

⚠️ 一个直接后果：源码必须以 **Java 8 字节码 + `-bootclasspath android.jar`** 编译，
而 `android.jar` **没有 `java.lang.invoke`**，所以**不能用 lambda 与方法引用，要用匿名内部类**。
这是 JVM 层面的编译错误，不是风格问题。

### 7.2 外网间歇可用

会话开始时 `curl` / `Invoke-WebRequest` / Node `fetch` 可能全部失败
（`schannel: AcquireCredentialsHandle failed (SEC_E_NO_CREDENTIALS)`），随后又恢复正常。
**这是沙箱侧的间歇性故障，不是配置问题。**

应对（已在代码里）：

- 所有下载走 `Get-FileOnce`（`common.ps1`），**自带 4 次重试 + 5 秒间隔 + 磁盘缓存**（文件非空即跳过）。
- **不用 `curl.exe`**，改用 **Node 的 TLS 栈**（`fetch`）——本环境的 `curl.exe` 会因 schannel 报错。
- URL 以 **Base64** 传给下载器：Debian 文件名可能含 epoch 冒号（`openssl_1:3.6.3_aarch64.deb`），
  而 PowerShell 会**在冒号处切断原生命令参数**，导致 node 收到 scheme 为 `https` 的错误 URL。

### 7.3 宿主虚拟显示适配器会崩模拟器 GPU 路径

本机装有 Oray / GameViewer 一类**虚拟显示适配器**，硬件 GPU 互操作路径可能崩：

```
Failed to find ColorBuffer
```

**应对**：模拟器一律加 `-gpu swiftshader_indirect`（软件渲染）。慢一些，但稳。
`dsh-test.avd\config.ini` 里也固化了 `hw.gpu.mode=swiftshader_indirect`。

### 7.4 arm64 模拟器不可行

**现代 Android 模拟器拒绝跨架构运行**，arm64 镜像在 x86_64 主机上直接 FATAL：

```
FATAL | Avd's CPU Architecture 'arm64' is not supported by the QEMU2 emulator on
        x86_64 host. System image must match the host architecture.
```

因此 **arm64 只能在真机（或 arm64 主机）上验证，没有捷径**。
`system-images;android-34;google_apis;arm64-v8a`（8.32 GB 系统镜像里的一部分）已下载但本机跑不起来。

> **为什么还要维护 x86_64 这一路**：app 只有 arm64 库时，x86_64 主机只能用 QEMU 翻译跑 arm64 镜像，
> 一次迭代（解包 ~190 MB + 启 Node）要几十分钟；x86_64 镜像走 WHPX 原生速度，编辑-运行循环才可用。
> 两个 ABI 共用同一套流水线（`-Abi` 参数），APK 里可同时带两套 `.so`。

## 8. 故障排查

### 8.1 构建期

| 症状 | 根因 | 处置 |
|---|---|---|
| `sdkmanager`: `Failed to download any source lists!` | 未先 dot-source `android-env.ps1`，写 `%USERPROFILE%\.android` 被拒（**不是网络问题**） | `. tools\android-env.ps1` 后重试 |
| `JDK not found. Expected a bin\javac.exe under …\jdk-21` | JDK 未解压，或层级超出 `-Depth 3` | 确认 `.toolchain\jdk-21\**\bin\javac.exe` 存在 |
| `cmdline-tools not found. Expected …\cmdline-tools\latest\bin\sdkmanager.bat` | 解压目录名不是 `latest` | 改名或在 `android-env.ps1` 内改路径 |
| 任何 adb 调用直接崩 | `C:\Users\yue\.android` 不存在（adb 硬编码该路径） | 建目录，见 [§5.3](#53-android-必须存在) |
| 下载失败 / `fetch failed` | 外网间歇不可用 | 重跑（脚本自带 4 次重试）；确认没在用 `curl.exe` |
| `unknown scheme` 的下载错误 | URL 里的 epoch 冒号被 PowerShell 截断 | 走 `Get-FileOnce`（Base64 传 URL） |
| npm 装不上 koffi（`EBADPLATFORM`） | npm 按**宿主**校验 `os`/`cpu` 字段 | 已由 `stage-engine.ps1` 直连 registry 抓 tarball 绕过 |
| `npm install` 想编译 koffi（要 CMake） | 缺目标平台预编译 | 确认带 `--os=android --cpu=arm64` |
| `cannot execute: required file missing` / 依赖闭包报 `missing` | `DT_NEEDED` 闭包不全 | 重跑 `stage-runtime.ps1`，看末尾闭包输出必须无 `missing` |
| javac 报 lambda / 方法引用错误 | `java.lang.invoke` 在 `android.jar` bootclasspath 下不存在 | 改匿名内部类（见 [§7.1](#71-gradle-守护进程无法启动)） |
| 写 `.ps1` 后解析报奇怪的字符串错误 | PowerShell 5.1 按 ANSI 解码无 BOM 文件 | 脚本保持 ASCII-only |

### 8.2 运行时（构建成功但设备上不对）

先收报告，再动手：

```powershell

```

它一次收齐：设备信息、安装版本、进程与界面状态、UI 轮询的 `engine-state.txt`、引擎失败日志、
引擎 logcat、WebView 控制台与版本、解包后的目录结构。

| 症状 | 根因 | 处置 |
|---|---|---|
| 卡在启动页，日志却「健康」 | 两个进程各有一份 `static`；或残留 state 指向死端口 | 见 `NEXT-SESSION-HANDOFF.md` |

| `CANNOT LINK EXECUTABLE: library "libz.so.1" not found` | 带版本号 soname 被 Android 安装期丢弃 | `elf-patch-needed.mjs` 改写为无版本名 |
| `Cannot find package '@dsh-mobile/...'` | 加载器从 **profile 树**解析，插件只在引擎树 | 启动时复制到 profile 树下 |
| UI 连不上、`connection lost, retry #1…#7` | 旧 WebView 缺 `AbortSignal.any` 等 | `WebViewPolyfills.java` 兜底 |
| 设备在跑过期引擎树 | 版本标记不够内容相关 | `ENGINE-VERSION` 已折入 `files=` 与 `bytes=` |

完整清单见 [`NEXT-SESSION-HANDOFF.md`](NEXT-SESSION-HANDOFF.md) 的「历史障碍清单」。
